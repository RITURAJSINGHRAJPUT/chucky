**Capiche Surat + Ahmedabad drinks editors** (2026-07-13, live at `/capiche-surat/` and `/capiche-ahm/`, tiles in the `/chucky/` picker). Part of [[chucky-aiko-editor]]. Source PDFs: `~/Downloads/Capiche - Drinks Menu (1).pdf` (Surat, cover + 1 menu page, ~10 mocktails) and `~/Downloads/Capiche Ahm - Drinks Menu (2).pdf` (AHM, cover + 3 pages: mocktails + coffees + iced/specialty). These are **text + photo** menus (single left column: name/desc/[vol]/price + Jain "J", photos on the right) — NOT gradient bands like Aiko drinks.

**Pipeline** (`src/capdrinks/`): `build.py <src.pdf> <outdir> <brand>` embeds **RobotoMono-SemiBold as `/RMSB`** (WinAnsi TrueType, `embed_ttf` via pikepdf: FontFile2 + Widths[32..255] + FontDescriptor) into every menu page, saves menu.pdf UNCOMPRESSED (⚠️ BOTH saves need `compress_streams=False, stream_decode_level=generalized` — the 2nd save silently re-compresses by default → span offsets break), parses `(...)Tj` runs with byte spans + tracked Tm/Td positions + font, stores per-page `reg_font`/`bold_font` resource names (⚠️ AOMonoRegular is `/T1_1` on page1 but `/T1_0` on pages 2-3 — resource names differ per page!). `group.py <outdir>` groups runs into drinks: name = size≥12 runs; price = `reg_font` all-digit run (val≥20); desc = bold-font body; vol `[..ML]` is a kerned TJ my Tj-parser skips → left baked/non-editable.

**Font-subset fix (the reason for RobotoMono):** the menu AOMono is subset — AOMonoRegular price digits only `0235` (no 1,4,6,7,8,9). Editor renders a price in ORIGINAL AOMono when all its digits ∈ allowed (`0235`), else deletes the original Tj + stamps `/RMSB size Tf x y Td (price)Tj` (RobotoMono, slightly bolder but any digit works). Name/desc stay byte-spliced AOMono (subset-limited → `cleanField` strips unavailable chars + fontNote toast, like Aiko drinks / food editors).

**Engine** (`deploy/public/capiche-{surat,ahm}/index.html`, identical code, brand-swapped): reuses the Aiko-drinks warm-dark SHELL (cards with name/desc/price inputs, page tabs, inline preview) + spell + chucky mascot + the shared [[chucky-aiko-editor]] EDIT-MEMORY module (autosave/resume/history; MEM_BRAND `capiche-surat`/`capiche-ahm`). `regenerate` = spliceBytes(name/desc via wrapTo into their line-spans; price conditional AOMono/RMSB) + append RMSB stamps, per menu page. No harness file — validated by node+jsdom boot + pymupdf render (`scratchpad/surat_edit*.png`).

**ROW-PITCH BUG — the real cause of the add/remove glitch (2026-07-15, fixed, deployed f88a4c8c). THIS supersedes the earlier "variable-height reflow" fix, which was wrong.**
These drinks menus are a **uniform row grid = the PHOTO STRIP**: every photo tile is 66pt tall and they tile continuously (Surat page1 tile ys 529.2/463.1/396.9/330.8/... → pitch 66.1-66.2). The **text tops do NOT follow that grid** — they sit at variable offsets inside each band depending on whether the name wraps to 1 or 2 lines. So the gap between consecutive text tops varies wildly (Surat: 58.4, 81.8, 74.8, **43.8**, 80.5, 51.8, 68.3, 66.2, 40.4).
I had set `it['pitch'] = top_y[i] - top_y[i+1]` (the TEXT delta) and reflowed by it. Consequences: remove SUNSET (text pitch 43.8, real row 66.1) → shift 43.8 → **22pt hole in the photo strip**; remove MINT (text pitch 81.8) → over-shift → **overlap** (Yash's original complaint). The old uniform `ROW=60` was also wrong (6pt short per removal → drift).
**FIX:** pitch = the photo-strip grid → `pitch[i] = photo_tile[i].y - photo_tile[i+1].y` (last row = its own tile height 66). Patched into both fieldmaps AND `reflow_data.py` as an **order-safe POST-PASS at the end of the page loop** (photo_tile is only assigned partway through that loop — computing pitch earlier reads None). Engine: added drinks now drop onto the grid — `lastTileY = lastSurvivor.photo_tile[1] + shiftOf(...)`, `tileY = lastTileY - ROW*(i+1)`, `by = tileY + 46`; photo/placeholder tile drawn AT tileY. Add-gate is now simply `maxAdd = (# removed on this page)` — one removal frees exactly one row (was `freedSpace/48`).
**GOTCHA:** `ROW` must be the **median** pitch, not the first item's — AHM page1's first row is an outlier (74.1 vs 66.1); using it pushed added drinks below y=0 so they silently didn't render at all.
Verified by render: remove-only closes the strip seamlessly; remove-2/add-2 tiles continuously incl. placeholder tiles; AHM likewise. If reflow ever looks wrong again, check pitch vs the photo-tile spacing FIRST.

where cropX/cropY (top-left) & cropW are in ROTATED-image px (effW/effH swap iw/ih at 90/270), and the inverse (`frameToBox`) opens the box on the current crop. `clampBox` keeps the box inside the displayed image → guarantees no background shows (equivalent to `photoClamp`). Handles resize anchored at the opposite corner/edge-centre; ratio locked to `tw/th`. On **rotate**, the frame RESETS to the centred cover for the new orientation (predictable; re-crop after rotating). Verified via a 4-quadrant test JPEG → framh.js render → pymupdf tile-colour sample: top-left crop → RED, bottom-right → YELLOW, cover → all-four blend, rot90 cover → 4 colours with ZERO dark background, rot90 top-left → uniform single quadrant (no distortion).
